# 密钥存储与升级验收

前端不再持久化 Key。独立后端插件通过酒馆原生密钥管理器存储当前账号的连接记录；普通设置只保留地址、模型和生成参数。模型列表及生成由后端请求，状态接口只返回是否有密钥。

## 部署

1. `npm test`、`npm run build`。
2. `node scripts/deploy-server.mjs <SillyTavern-root>` 安装后端插件；`node scripts/deploy-model-side.mjs <character.png> <SillyTavern-root>` 备份并升级指定角色卡。
3. 重启酒馆服务，再刷新目标聊天。只有刷新页面不会加载新后端。
4. 设置页初始化时把旧浏览器记录迁入当前登录账号；后端回读一致后删除旧记录。出现“后端密钥存储已就绪”且“后端已保存密钥”，才表示本浏览器迁移成功。失败显示红色通知，不删除旧数据，不启用操作按钮。
5. 不重新填写 Key，测试拉取模型与连接；保存后刷新再次测试。开发者工具只检查旧存储项是否不存在、返回是否仅有布尔值，禁止打印密钥值。

未重启及刷新前，不能声称实际用户密钥已迁移或清除。其他浏览器／旧页签的副本须各自刷新迁移；服务端已有不同密钥时返回冲突，不悄悄覆盖。只存在安全隐患不等于已泄露；若确认泄露，应在供应商处轮换。

## 安全边界

- 当前只接入 OpenAI／OpenAI 兼容的 `/models`、`/chat/completions`，不影响酒馆正文 API，不调用 Amily 密钥接口。
- 继承酒馆登录、CSRF 和账号目录隔离；本插件没有返回明文密钥的接口。不要开启酒馆全局 `allowKeysExposure`。
- 保存的 Key 与基础地址绑定，不能通过请求参数改投其他域名。远端要求 HTTPS，回环本机允许 HTTP；代理与兼容处理复用酒馆原生模型列表和生成通道。
- 后端原生密钥文件及历史备份仍需要系统访问权限保护；不宣称磁盘加密。恶意同源脚本仍可能盗用登录会话、拦截新输入，后端保存不替代插件可信审查。
- 错误不透传上游正文，不打印请求头或密钥；成功响应若回显当前 Key 则替换为隐藏标记。
- “未保存的 Key”仍可用于单次连接测试，但仅随请求交给本机后端，不写入浏览器存储；只有点保存才持久化。

按 ponytail 未引入 Amily 的密钥对、私钥导入导出、多连接槽管理，也未新增依赖。
