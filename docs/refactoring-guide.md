# 成就系统与手账架构约定

作者编辑使用独立的 `AuthorSession/AuthorStoragePort`，页面 → 作者用例 → 共享领域规则 → 账号文件适配器。作者保存通过最小读写互斥、修订检查及完整目录提交，不进入玩家提交队列。具体定义见[作者契约](contracts/authoring.md)。

本文维护分层、提交、状态应用和数据保护约定。存档与玩家接口见[数据契约](contracts/README.md)，选材与响应见[模型契约](contracts/child-api.md)，资源和版本流程见[内容包契约](contracts/content-packs.md)。历史差距、实施阶段和部署记录不作为当前架构说明。

## 分层与存储边界

内容包加载通过应用侧 `ContentPackPort.load(binding)` 表达，酒馆适配器负责 HTTP 路由、响应校验和资产 URL 生成。版本预览及确认时来源／目标版本复查使用同一端口；应用代码只使用已校验的内容和资产地址映射。密钥操作通过 `SecretsPort` 注入，实际实现仍使用现有插件后端与酒馆原生通道。

玩家交互通过 `runtime/player-port.ts` 的 `PlayerUseCases`，设置与世界书页通过 `settings/ports.ts` 的 `ApiSettingsPort`，提示词页通过 `prompting/ports.ts` 的 `PromptingPort` 使用应用功能。版本页继续使用已有 `PackVersionsPort`。前端 `JournalPort` 组合玩家业务接口与布局、DOM 挂载能力；宿主 handle 组合业务接口与生命周期。业务契约不包含 DOM 或宿主类型，具体控制器与宿主适配器由启动入口装配。

`tests/port-boundary.test.mjs` 检查应用代码的静态／类型导入、重导出及动态导入，阻止依赖 UI、创作稿或 HTTP／宿主适配器；页面通过接口使用控制器。业务契约及依赖闭包另在不含 DOM 和酒馆全局声明的环境中编译。外层启动代码允许装配具体实现，已有领域与正式包的演示边界检查继续保留。

| 层 | 职责 |
| --- | --- |
| 协议解析与校验 | 提取模型 JSON，检查字段、请求身份和本次发送权限 |
| Runtime | 自动／手动调度、聊天材料范围、网络调用、响应有效性、内容加载和提交协调 |
| Domain | 节点前置、互斥、任务流转、达成、重新上锁及玩家视图 |
| 统一提交入口 | 在队列内读取最新状态、调用 Domain、合并改动、保存和发布视图 |
| 存储适配器 | 保存到正确聊天，处理宿主保存失败，保留其他元数据 |
| Renderer | 消费视图与场景，呈现交互并提交玩家命令 |

Domain 只处理普通对象，不导入酒馆环境或网络请求。空存档定义位于 `src/domain/save.ts`；领域公共出口不导入创作稿或演示数据。示例目录与请求／响应夹具位于 `src/content/examples.ts`，仅供预览和测试使用。发送筛选与提交复核共用领域规则；前端通过查询和命令入口使用这些规则。保留聊天存档兼容性，沿用现有框架与默认纸纹样式。

公有内容包相当于游戏数据包，包含预设树、条件、前置、布局、图片及有限主题。角色卡保存包绑定；内容包独立于角色卡和聊天存储，删除卡或聊天不删除公有资源，仍需单独备份。

私人存档随聊天 JSONL 保存节点进度、接取／待领取事实、生成留言、玩家改写、日记、当前章、自动游标和内容身份。存档不复制完整树、布局或图片；新聊天空进度，复制聊天继承进度和包绑定。

账号保存通用连接配置；角色专属提示词和世界书绑定的归属调整按对应配置契约实施。密钥规则见[密钥存储说明](backend-secrets.md)。

通用 Renderer、执行代码和基础 CSS 由插件维护。内容包只提供数据、图片和有限主题配置，不能通过节点内容执行脚本或任意 CSS。运行时将公有定义与当前聊天记录对齐，生成统一快照供界面使用。

正式入口优先读取角色卡或当前聊天绑定的发布内容包，也支持宿主显式注入目录。未提供内容时报告缺少绑定并保留设置入口，不启动内置示例。`npm run build` 只生成前后端运行脚本，其类型检查和打包不依赖创作稿；`npm run build:preview` 单独生成使用草稿与内存进度的离线手账预览。

## 内容包与资产

- 作者维护仓库中的 `content-packs/<packId>/draft/`；玩家读取账号目录中的 `goblin-achievements/packs/<packId>/releases/<packVersion>/`。
- 内容包括 `manifest.json/catalog.json/layouts.json/theme.json/assets/`；详细资产层级和命名只在[内容包契约](contracts/content-packs.md#数据真源与目录)维护。
- `assetRef` 是包内相对路径，采用正斜杠；拒绝绝对路径、网址、越界和未登记引用。旧 `imageName` 通过显式映射兼容。
- `schemaVersion` 是格式版本；`packVersion` 是字符串发布版本，例如 `"0001"`。旧聊天保持原版本，新内容通过显式升级使用。
- 发布版本不可原地覆盖。草稿变动须校验、发布新版本并切换内容实例；目录自动发现只负责登记，插入位置由 `assetRef` 指定。
- 作者发布时完整校验内容与所有图片；运行加载只检查清单、内容文件和资源引用，图片按需请求并校验。缓存与哈希策略见[内容包契约](contracts/content-packs.md#发布加载与用户验收)。
- 内容加载失败保留原实例；已经切换聊天时禁用旧实例入口，避免展示其他聊天进度。合法内容与绑定保存成功后才激活。

### 版本迁移

保持稳定 ID；改显示名不改 ID，节点含义变化时新增节点。迁移使用来源版本及指纹明确的映射，支持一对一改名与明确删除。冲突、目标缺失、跨模块或改变任务类型不能作为改名迁移。

迁移同步处理节点进度、接取／待领取事实、撤回暂存、纠错、卡片归属及章节引用。卡片、日记、请求和旧消息来源 ID 是独立身份；日记、自动游标和已处理请求不因升级重置。

删除或新前置／互斥导致失效的记录归入遗留区，保留原包、ID、时间、生成文案和玩家改写，不参与当前前置或计数。图片删除只处理引用，不删除实际文件或成就文字。

升级先预览再确认，在同一提交队列内转换、校验和保存；失败保留原包、存档与视图。预览后任何存档变化都须重新预览，这是迁移确认保护，与模型响应的后提交覆盖规则分别处理。

`packRollback` 保存上一版本的记录快照，支持一步往返，不含静态资产或嵌套恢复快照。代码回滚与内容版本恢复分别处理；旧代码未必能读取新存档。具体映射、遗留记录和恢复入口见[版本迁移契约](contracts/content-packs.md#阶段-c显式版本迁移)。

## 自动与手动判定

自动发送仅处理最新一轮用户输入与清洗正文。频率设置决定何时触发，不扩大材料范围，也不补发历史；忙碌期间只保留最新待处理楼层。续写没有新用户输入时不补历史输入。

用户输入与清洗正文用于剧情、人物及怪物树检索；世界书人设只检索所选范围的用户输入。自动请求附带本轮用户原文；手动范围由玩家指定。具体选材、当前章及任务规则以[模型契约](contracts/child-api.md#模块材料装配触发与边界)为准。

只有自动判定提交更新 `processedThrough`；手动判定、玩家编辑和重新上锁不推进或回退自动游标。两种判定共用同一存档与提交入口。

重新上锁不建立正文证据黑名单。以后旧正文或新正文均可重新判定，但必须满足当前前置、互斥、任务状态及请求权限。新结果不保存逐项正文来源，因此当前不根据删楼或重生成自动撤回新成就。

## DAG 前置与任务约束

提交时按最新状态检查候选范围、前置、互斥和任务流程。同一字段后提交的合法修改可以覆盖旧值，但不能借此补亮前置、自动接取或提交非法状态。

| 操作 | 处理 |
| --- | --- |
| 锁回 A 后，模型再次提出达成 A | 当前前置与流程合法时可重新达成；成长任务须重新接取 |
| B 依赖已锁回的 A，模型只提出达成 B | 拒绝 B，不补亮 A |
| 锁回前置 A，已有后继或进行中任务依赖 A | 级联撤回后继并清除受影响任务事实 |
| 任务已撤回接取，模型仍返回完成 | 按最新任务状态拒绝，不自动重新接取 |
| 模型更新合法附文 | 覆盖该字段，保留未涉及的玩家改写；combat 静态介绍不接受模型改写 |

仅 combat 允许使用本批明确返回并已接受的同树前置，按 DAG 顺序处理；父节点拒绝则依赖项拒绝。其他模块按批次开始前的最新状态校验。没有被模型返回的节点均不得自动补亮；更新数量由[模型契约](contracts/child-api.md)统一规定。

身份、协议或权限错误拒绝整批。单项业务条件不成立可以跳过并记录原因，独立合法项可保存；最终状态必须合法。拒绝项不挂起或自动复活，后续重新判定使用新请求。

## 日记与文案覆盖

日记允许内容重复，同一段正文可以在不同合法请求中生成多篇日记。重复请求回调仍须去重；每请求数量限制沿用模型契约。

玩家按日记 ID 编辑目标条目；模型新增日记只追加记录。模型当前没有编辑旧日记的提案。修改日记不阻止独立成就结果保存。

玩家和模型对同一可编辑字段均以后提交的合法修改为准，不额外给予玩家编辑优先权。模型未涉及的日记、名字或附文必须保留。

### 三、统一提交、手动修改冲突与请求去重

#### 3.1 合并原则

提交时读取最新已确认存档，在工作副本合并本次改动。禁止用请求发出时的整份旧快照回写，避免覆盖等待期间其他合法修改。

模型响应不要求 `currentRevision === baseRevision`。普通日记编辑、提醒标记或节点修改不使整批响应失效；提交仍须复核最新领域条件。

#### 3.2 职责分工

所有领域写入经过 `AchievementMetadataRepository.commit()`。网络生成在队列之外等待；解析后的模型结果与玩家命令进入同一队列。通过聊天元数据保存的发送配置使用 `coordinate()` 共用保存通道。各层职责按本文开头的分层表执行。

#### 3.3 提交流程

每次提交依次执行：

1. 核对目标聊天、内容包、发布版本与内容实例。
2. 在队列内读取最新已确认存档。
3. 检查请求是否已处理，复核领域条件。
4. 在工作副本中合并更新，检查最终状态。
5. 一次保存改动、请求结果和本次自动游标。
6. 保存成功后发布统一视图并通知，再处理下一项。

可以保存最新合并后的完整快照。保存失败恢复本次字段并保留其他元数据，不发布未保存状态，后续队列仍可执行。

#### 3.4 队列作用域与聊天身份

同一插件实例的接取、领取、上锁、日记、模型结果、提醒、当前章和存档迁移共用 FIFO 异步串行队列。排队前绑定聊天，执行和保存后复核身份；内容实例替换也共享此队列。

切换聊天使原请求失效；结果不得写入新聊天。如果宿主保存已经发出，此时切换聊天不能承诺取消该保存，应提示回原聊天核对。

队列只保证单实例串行化；多标签、多设备并写不在当前范围内。

#### 3.5 revision 与请求防重复

`revision` 标记快照变化，`requestId` 标识一次判定，两者用途分开：

- 同一手动预览失败重试沿用请求 ID；重新预览或主动重判使用新 ID。
- 自动请求按本轮输入及实际材料确定身份，不以普通存档修订变化重新定义同一次请求。
- 重复回调不追加日记、不重复通知、不补执行此前拒绝项。
- 部分拒绝的响应也记录处理结果，未来状态改变不能使旧回调偷偷生效。
- 所选正文／用户输入、聊天、配置、准入或内容身份变化时，按 Runtime 的在途有效性规则废弃旧响应。
- 内容版本迁移预览按完整存档检查，变化后重新预览；不能将这条规则用于拒绝普通模型更新。

#### 3.6 通知与界面

实际修改并保存成功后，复用 `src/notifications.ts` 播报一次写入完成，简要说明跳过项。失败报告失败；无变化且无拒绝项、重复回调均不播报。不另加覆盖玩家文字的确认框。

节点、场景和红点使用同一份提交后快照。玩家操作、自动与手动判定成功后刷新已打开手账；切换聊天关闭或重载手账与编辑器。

设置页行内反馈使用 `setStatus(root, message, level)`，同时弹一次通知；省略 level 只更新行内状态。通知由 UI／调度入口负责，数据层返回结果或错误；消息按纯文本处理，不包含密钥、完整请求或模型原文，不修改宿主全局 toastr 配置。

## 后台创作与后续扩展

创作稿 → 校验并发布只读版本 → 角色／存档绑定 → 内容加载器 → 公有定义与私人记录 → PlayerView → JournalScene → 玩家界面。

可视化编辑器、目录自动登记和生图管理尚未实现；后续都写入创作稿，再经过已有发布流程。自动章节完成、结局计数、旅行地点计数与追加见闻仍属后续工作，不能按草案字段写入当前存档。
