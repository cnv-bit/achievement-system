# 模型侧：请求、响应提取与交接

目录版本 3 的准入规则见[作者契约](authoring.md)。新目录使用本地定义和进度作为基础白名单，保留可选外部限制。剧情按当前阶段与树关键词粗筛，命中后整树发送成就、依赖和完成状态；隐藏入口不作为成就发送，剧情无需接取或领取。其他版本 3 模块沿用五态候选准入。模型结果在提交时再次复核前置和互斥，不能用本批提案满足剧情或额外前置。版本 2 沿用下文原规则。

设置／世界书页面通过 `ApiSettingsPort` 调用现有配置控制器，提示词页面通过 `PromptingPort` 调用预览与确认发送。密钥依赖 `SecretsPort`，由原 `BackendSecrets` 接入插件后端；模型生成与列表仍走酒馆原生通道。接口定义只整理调用边界，不改变下文请求、响应及提交协议。

## 职责与处理流程

交付目标：玩家配置连接和提示词、选定剧情与模块后，得到判定结果，经唯一数据入口保存，并看到成功、无更新或失败的明确反馈。

- 全局职责见 [AGENTS.md](../../AGENTS.md)，系统概览见 [根目录概要](../../PLAN.md)。
- 本文件维护模型请求、响应及交接协议；存档与玩家行为见 [数据契约](./README.md)，尚未落地的需求见 [本地侧计划](./PLAN.md)。
- 模型侧负责 API 配置保存、拉取模型列表、连接测试，提示词／判定思考要求编辑，正文楼层与模块选择，自动／手动发送，最终提示词预览，返回信息提取与请求权限校验。对应 `src/settings/`、`src/prompting/` 及请求、调度、解析代码。
- 用户与数据库侧负责提供七模块的候选内容与当前状态块、人物绑定与角色级模板归属，以及节点规则、去重、撤回、应用和成就保存。模块内装几个任务、节点或技能由对方决定；模型侧不重建候选业务规则。
- 人物树彼此独立，无跨人物前置。模型侧按模块开关、关键词命中与数据侧准入组装树和状态；关键词命中只决定发送，不直接解锁成就，不处理人物关系。
- 混合入口 `achievement-runtime.ts`、酒馆适配器、共享字段和构建配置，先由总协调线程确认拆分归属。

### 请求处理流程

1. 读取用户与数据库侧提供的模块内容／状态块、准入、当前章节及版本；按玩家勾选的模块与下文关键词规则选图。世界书人设另外只扫描对应范围的用户消息。
2. 固定本次聊天、剧情版本、模块权限、提示词及相关材料；发送前展示最终完整提示词，再使用同一份请求快照调用独立子 API。
3. 按下文协议提取、解析、校验；过期或越权结果不进入数据应用入口。
4. 将已校验结果和程序生成的处理范围交给用户与数据库侧；以其保存结果反馈完成状态。

“更新提案协议”就是双方约定的返回格式和字段落位规则，不是额外服务。模型只返回 `schemaVersion/judgementSummary/updates`；程序加戳后的内部交接沿用 `ChildApiResponse`。`judgementSummary` 是简短判定摘要，解析不依赖模型私有推理或标签外的自由文本。

### 请求身份与正文来源

- 模型不填写 `requestId/chatId/baseRevision`。接入层从本次发送快照补齐三字段，不读取返回时的当前聊天或新修订号；模型若仍返回旧身份字段则提示修改已保存的提示词并拒绝，不采信或覆盖程序身份。
- 同一手动预览失败重试沿用请求 ID；重新预览或主动重判生成新 ID。自动请求身份不包含普通存档修订号。已接取任务可以用旧正文补审，仍须经过当前准入与任务校验。
- 模型返回及内部提案都不再包含 `sourceMessageIds`，也不把整批正文复制成每个结果的来源。新节点、卡片、日记的 `sourceRefs` 留空；存档版本 7 继续兼容旧记录，不清除历史来源。
- 保留在途的聊天、输入、配置、准入与内容身份检查，以及 `appliedRequestIds` 去重。普通存档修改不触发全局 revision 强等拒绝，提交时按最新领域状态复核；摘要随结果返回，不另存历史。
- 手动锁回必须连锁撤回全部后续依赖，避免前置已锁而后续仍亮。重新达成只复核当前前置、互斥和模块规则，不区分旧证据或新证据；请求防重复也不等于跨请求的正文去重。新记录不带正文来源，因此不能据此定位某段正文自动撤回。
- `prompt-content.md` 和 `prompts.md` 是写作参考，不会自动覆盖玩家已保存的提示词；设置页里的旧字段要求须由玩家删除后保存。固定输出协议已同步简化。

## 模块材料装配：触发与边界

- **关键词适用范围**：剧情地区树、人物与羁绊、怪物／战斗成就树。剧情同时限定当前大阶段；职业、技能、知识由接取状态选材。旅行与日记沿用各自规则。
- **关键词扫描范围**：扫描玩家选定楼层范围内的全部用户消息，以及本次实际发送的正则清洗后助手正文；被清除的思维链、小剧场、自检不参与匹配，不扩展到范围外历史。
- **逐正文自动范围**：选择每次正文生成后自动发送时，仅匹配本次生成对应的用户输入与本次一篇清洗后正文，不沿用最近多轮窗口；回合范围由发送调度提供。
- **模块开关**：只认七大模块开关；未勾选模块不装入上下文。具体人物／树／条目的旧手动勾选不改变人物关键词、成长任务或剧情阶段规则。
- **关键词归属**：剧情树 `storyTrees[].keywords`、人物 `keywords` 与战斗树 `keywords` 复用普通文本和可选 `/正则/flags` 匹配；任意关键词命中即可选树，不按名字猜测。多个命中树按稳定 ID 各装入一次；职业树、技能树、知识主题的关键词字段不用于选材。
- **任务装配**：职业、技能、知识只装入当前 `active` 节点；同次全部装入，不要求关键词命中，不发送 `blocked/available/claimable/completed` 节点或历史卡片。模型的解锁提案把任务变为 `claimable`，玩家领取后才写入 `completed`。前置由数据层确认，隐藏的已完成前置只用 `externalPrerequisitesSatisfied: true` 表示。
- **关键词未命中**：剧情、人物或战斗不发送对应树及状态；某模块无获准材料时也不发送其提示词或授予更新权限。剧情关键词缺失、为空或未命中均不回退为全章发送。若所有模块均无材料则跳过 API 请求；旅行与日记按独立规则处理。
- **剧情阶段与树筛选**：从数据上下文的 `currentChapterId` 读取当前大阶段，未提供则读当前成就存档。设置页显式选择并经原元数据入口保存；不会自动开放或完成章节，也不推算最高章。先限定当前章与准入，再匹配地区树关键词；命中后装入该树的当前章节点，不逐节点匹配，其他树及其他阶段不发送。
- **跨章长线**：剧情节点可选 `chapterId`，未填沿用所属树的 `chapterId`。只发送当前章切片及状态。已达成的跨章前置不暴露 ID，材料用 `externalPrerequisitesSatisfied: true` 表示；候选只带切片内的前置 ID。原目录的完整前置关系不变，落库仍用完整目录和存档检查；未达成的跨章前置或隐藏的同章前置导致依赖节点不发送。
- **数量与职责**：每次请求每个启用模块最多返回一个成就，combat 怪物图鉴例外，可返回多个不同候选且不占技能名额；多个 active 任务、多个剧情树、批量正文不增加其他名额。模型侧负责装配和请求权限；数据侧负责任务状态、当前阶段、前置与节点应用。响应加戳和不记录新结果正文来源的约定不变。

实现入口：`request-builder.ts` 复用现有关键词匹配，并调用数据侧统一任务状态函数。提示词页只保留旅行地区勾选并显示实际发送材料；无材料时预览无提示词、发送按钮禁用，运行接口返回 `skipped: true`，不调用模型、不保存结果、不推进游标。`autoEveryRounds = 1` 固定只取本篇正文，用户范围仍是前一篇助手回复之后、本篇之前的所有用户消息；续写无新输入时不补历史输入。

当前章通过插件句柄的 `getCurrentChapterId()` / `setCurrentChapter(chapterId)` 读写；写入递增修订号并使旧预览失效，按当前聊天隔离。外接准入回调显式提供的阶段优先于存档字段，应与该存档保持一致。

## 世界书用户输入匹配与正文发送

本节的“仅用户输入匹配”只适用于世界书人设；剧情、人物与战斗树的检索按上节“用户输入＋清洗正文”执行。世界书匹配不会替代各树归属关键词，也不决定任务或剧情材料。

- 设置页可选择世界书、整本绿灯条目或指定条目，并单独勾选公共背景；保存和重新读取均走现有设置及酒馆读取入口，不改世界书内容。
- 范围内全部用户消息以分隔符组成一个扫描缓冲，主要／次要关键词都在这个缓冲上匹配；不向前补用户输入，不推断配对。助手正文、被过滤标签、已匹配世界书内容不进入扫描缓冲。
- 只用条目关键词匹配，不用条目名字或 UID 猜人物。UID 仅用于保存选择和去重。没有用户消息时静默略过关键词条目，显式公共背景仍按配置加载。
- 世界书命中提供模仿留言和说话所需人设，不直接解锁成就或地点。各模块候选及状态按上节选取，不依赖世界书条目是否命中。
- 本规则只影响成就子 API，不修改酒馆主 API 的世界书绑定与触发状态。
- 手动范围可只包含助手正文，不提示缺少输入。范围内没有可用正文时提示，不发送空剧情。
- 发送前展示最终完整提示词：消息角色、实际排列顺序，以及展开后的规则、世界书、正文、变量、候选、文风、判定要求和输出协议；不是仅展示模板或章节标题。Key 不属于提示词，不展示。
- 手动预览与发送复用同一份组装结果；材料或配置变化后重新生成预览。自动模式在总开关、模块开关和发送权限允许时触发，不逐次等待手动确认。

### 正文处理与预览

- 世界书读取复用 `SillyTavern.loadWorldInfo` 与原生宏展开。沿用 `WorldInfoBuffer.matchKeys` 的最小匹配算法与斜杠正则解析；不调用会混入主聊天和递归扫描的 `checkWorldInfo`。
- 支持主关键词、四种次关键词逻辑及全局／条目大小写和整词设置；跳过停用、蓝灯与向量条目，公共背景须显式选中。不模拟概率、扫描深度、递归、黏性或冷却。
- 正文清洗配置一条提取正则与逐行排除正则；最终规则由作者按正文样本填写。配置提取规则后，标签未命中或清洗结果为空时停止发送，不回退原文。
- 变量取所选最后一篇正文的 MVU 历史快照，仅发送准入回调明确提供的投影。
- 预览标出助手正文及参与关键词匹配的用户楼层；自动请求附带用户原文，手动请求仍用用户输入检索但不把它放入 `storyMessages`。
- 配置草稿先保存，手动发送复用当前预览 ID；提示词字段为 `taskPrompt/reasoningPrompt/modulePrompts`。`publicPrompt` 仅兼容读取，`styleRules` 不再读取。最终消息排列以 `buildOrderedPrompts` 为准。
- 表单视觉规范见[前端美术指南](../guides/frontend-art.md)。

### 数据侧准入对接

准入仍由数据侧提供；剧情按阶段＋关键词，人物／战斗按关键词，三类成长任务按接取状态选材。

入口：`start(catalog, readModelContext)`，或在启动前设置脚本环境的 `window.GOBLIN_ACHIEVEMENTS_MODEL_CONTEXT`。回调类型见 `src/runtime/model-context.ts`：`(messageId, historicalVariables) => { canSend, variables, currentChapterId? }`。回调只读；章节开放、人物激活和业务规则仍由用户与数据库侧计算。

- `canSend` 是以稳定 ID 为键的布尔白名单。模块键、对象自身、父级及节点必须都明确为 `true`；缺失或 `false` 一律拒绝。剧情切片需当前 `chapterId`，技能树需 `skillOwnerId`，知识主题需领域，地图地区需地图；带互斥组的节点还需该组准入。
- `variables` 是对传入历史快照的最小安全投影；数据侧不得把未准入人物／章节状态塞进这个对象。不需要变量时返回 `{}`。
- 聊天级 `selectedGroupIds` 仅用于旅行地区；旧人物／树选择不影响阶段、关键词或任务结果。请求附带局部 `moduleContext`；任务材料只含 `active`，非任务材料保留既有锁定／达成状态。
- 关闭旅行模块会取消并禁用地区选择，重新开启需重选；其他模块关闭后完全不选材或发送。世界书背景选择独立。
- 同章隐藏前置导致依赖节点不发送；跨章前置按上节处理，不泄漏其他章 ID，不修改目录规则。
- 用户输入、保存配置、数据侧准入／变量／当前章或实际任务材料变化时，旧预览在调用 API 前就被拒绝；返回时继续检查请求身份与材料。自动频率仅决定触发时机；所有自动请求均只处理最新一轮，不补发此前正文。
- 正式目录没有准入回调时默认不发送，不能“临时全部放行”。仅明确标注的技术骨架使用独立演示白名单。当前目录版本为 2、存档版本为 7；章节完成门槛尚未自动计算。

## 本侧配置与提示词约束

- 连接交互参考 Amily：来源、URL、Key、模型输入、拉取模型列表、连接测试与保存；连接跨聊天复用。自动开关与模块选择跟随聊天。
- 人物绑定与模板的角色归属由用户与数据库侧管理；本侧提供提示词编辑和发送功能，读取其提供的绑定／模板。未保存的提示词草稿不能发送，须先保存并重新预览。
- 世界书人设匹配支持酒馆绿灯的正则、整词、大小写及次关键词逻辑，仅扫描所选范围的用户消息；剧情、人物与战斗树匹配扫描用户消息和清洗正文，归属关键词之间为任意命中，不引入递归等额外行为。
- 正文中的标签思维链、小剧场和中间自检须滤除。用户会在编写正则时提供标准正文，届时按实际标签编写与验证，不预猜格式；标签缺失或无法可靠提取时暂停提示，不回退发送全文。
- 旧正文使用对应历史变量快照；没有快照时提示选择，不默认读取最新变量。只拼接判定所需字段，不维护剧情变量或成就状态。
- 各模块提示词要求：根据正文及当前状态块判断是否有达成，按共享协议返回 JSON 与文本；无达成可返回空结果。只允许玩家勾选的模块返回更新。
- 整次请求中，每个勾选模块最多返回一个成就，不区分树或正文数量；combat 怪物图鉴允许多个不同已发送候选，abilities 的 skill 仍最多一条；可不返回。
- 旅行与探索每次请求最多返回一个地点及一条见闻；随手日记最多返回一条。本侧将数量限制写入提示词并校验响应，超限报错，不擅自挑选或截断；具体记录的应用交用户与数据库侧。

## 提取方式

约定用一个 `<achievement-update>...</achievement-update>` 包裹下面的完整 JSON。模型侧可用正则定位标签内容，再用 `JSON.parse` 解析；不靠正则逐字段拆解嵌套 JSON。缺失、多个结果块或 JSON 无效时报告错误，不猜测写入。

当前 `response-parser.ts` 只提取唯一标签块并解析 JSON；缺失、重复或 JSON 无效直接拒绝。数量与文案政策由共享域校验处理：combat 可以多个，skill 和其他模块各最多一条。此提取正则固定在程序内部，不暴露给设置页。

## 请求白名单

模型侧按 `ChildApiRequest` 组装内部请求；管理身份留在程序中，实际提示词只发送：

- 本次允许更新的模块。
- 选定范围内经过标签过滤的助手正文及其来源标识。
- 本轮需要的世界观、人设片段和变量。
- 用户与数据库侧提供的本轮候选内容与状态：现有字段包括节点稳定 ID、条件、前置 ID、人物 ID 和必要的已解锁节点 ID。

请求正文不包含历史日记、旧留言、生成说明、玩家改写、界面状态、API Key 或完整存档；Key 只用于连接认证。候选与状态仅限本次模块启用且数据侧准入的材料：剧情取关键词命中树的当前阶段节点，人物／战斗取关键词命中树，三类成长取 active 任务，旅行保留地区勾选。用户输入用于剧情、人物、战斗和世界书人设匹配；是否附带用户原文继续沿用现有发送模式规则。

## 现有响应形状

以下示例遵循当前共享输出协议。地点见闻等未实现扩展须同步类型、校验、状态应用与提示词后才能使用；不能通过模型附加字段提前落库。

```json
{
  "schemaVersion": 1,
  "judgementSummary": "本轮明确发生重逢，也有一则适合记下的小插曲。",
  "updates": [
    {
      "type": "unlockNode",
      "proposalId": "unlock-demo-reunion",
      "module": "bonds",
      "nodeId": "bond.demo.reunion",
      "personId": "person.demo",
      "copy": {
        "description": "钟声落下时，两人终于在旧街重逢。",
        "memento": "下次别再迟到了。"
      }
    },
    {
      "type": "appendJournalEntry",
      "proposalId": "journal-clock",
      "module": "journal",
      "text": "她还是会在钟响前一秒出现。"
    }
  ]
}
```

`updates` 可以为空。除怪物图鉴 combat 外，每模块最多一个更新项，批量正文不增加名额。combat 可返回多个不同候选节点，不占用 abilities 技能的一条名额；不再有七项总上限。`proposalId` 和解锁 `nodeId` 在单次响应内唯一，不输出来源字段。

## 现有两类模型提案

`unlockNode` 适用于六个节点模块。本侧检查模块已授权、节点已发送、人物已激活及分类数量限制；前置、互斥、阶段顺序及纪念内容许可由用户与数据库侧检查。combat 禁止 `copy` 或模型自报 `nodeKind`；类型由已发送候选和目录确认。怪物同批初见及后续允许按本树 DAG 顺序达成，仅处理明确返回的节点，不自动补亮前置；其他模块继续按提交前状态校验。

`appendJournalEntry` 仅适用于 `journal`。可选 `title` 为 1—200 字的简短标题；省略时仍可正常追加，旧日记未命名显示“无题日记”。没有值得记录的经历时不返回该提案。日记不能借此修改旧条目。

## 交接与校验归属

- 模型侧：提取 JSON，从发送快照补齐请求戳，调用共享 `validateChildApiResponse`，检查字段白名单、程序请求身份、响应版本、启用模块、已发送候选与激活人物。发送期间聊天或选定正文变化则废弃响应。
- 用户与数据库侧：接收已校验结果与本地请求上下文，在统一提交队列内读取最新存档，检查目标聊天和内容身份、请求未应用，以及节点归属、前置/互斥规则、任务流程、纪念卡许可和日记长度等本地规则，再统一保存。不要求最新存档修订号等于发送时修订号。

同一字段规则只保留一处实现。模型侧按共享协议检查字段形状及本次发送权限；节点是否允许某种附言、是否首次达成由用户与数据库侧检查。响应是否对应本次请求与当前存档是否仍能接受结果是不同检查。

本地请求上下文携带原聊天、请求 ID、发送时修订号和各模块处理范围，由程序生成，不能让模型指定。身份、协议或权限错误拒绝整次请求；单项业务不满足时跳过该项并记录原因，独立合法项可以保存，拒绝项不在重复回调中补执行。仅自动判定推进自动处理位置；手动历史判定不改变它。保存失败不发布新状态，后续提交仍可执行。

## 字段放在哪里

用户与数据库侧按 `module` 和稳定 `nodeId` 找到预先定义的节点，不按展示名称猜测，也不允许模型创建未知节点或页面。

| 模型结果 | 本地落位 |
| --- | --- |
| 普通节点 `unlockNode` | 对应 `nodeProgress[nodeId]` 的解锁记录 |
| 三类任务 `unlockNode` | 对应 `nodeTasks[nodeId]` 的待领取事实；玩家领取后才转为 `nodeProgress` |
| `copy.description` / `copy.memento` | 普通节点直接进入 `generatedCopy`；任务说明先随待领取事实保存，领取时转入完成记录 |
| `appendJournalEntry.text` | 新增 `journalEntries` 条目的 `generatedText` |

本地侧负责生成条目 ID 和时间，保留模型未涉及的玩家改写；同一字段以后提交的合法修改为准，晚到的模型附文可以替换该字段的玩家改写。前端读取统一提交后的快照，按本地交互规则显示节点、附文和解锁效果，不再解析模型原文。

## 拒绝规则

校验器拒绝未知字段和未知更新类型，防止模型借额外字段修改本地状态。以下内容永远不是合法模型更新：

- `processedThrough`、`revision` 或 `appliedRequestIds`。
- 未随本次请求发送的旧节点文案，或直接写入玩家展示覆盖字段。
- 节点定义、关键词、条件、前置关系或互斥组。
- 未启用模块、未发送节点或未激活人物。
- 删除、回滚、重新锁定和批量替换存档。

同一逻辑请求重试沿用同一请求 ID 和相同输入；主动重判使用新 ID。聊天切换、选定正文／用户输入、配置或内容身份变化后，旧响应作废；日记编辑、节点编辑或提醒标记造成的存档修订号变化不使整次响应失效，提交时改按最新领域状态复核。详见 [统一提交约定](../refactoring-guide.md)。

共享字段变化须同步模型校验与数据应用入口。

## 接入要求与验收

正式内容需要宿主提供 `canSend` 准入回调；缺失时不发送。正文清洗正则和提示词由作者按实际剧情填写。设置页的生图连接测试只拉取模型列表，不代表已实现自动图片生成。当前提交使用统一队列，存档格式见[数据契约](./README.md)。

模型侧交付至少验证：

- 请求预览展示完整最终提示词并与实际发送一致；Key、历史文案、未激活人物及未授权候选不混入提示词；子 API 调用不污染主 API 内容。
- 没有用户输入也能处理有效正文且不警告；只有所选范围用户消息能匹配人设，助手正文／范围外输入不触发；人物／地点树状态与人设匹配相互独立。
- 标签缺失、多结果块、非法 JSON、未知字段、越权模块／节点／人物均被拒绝；旧身份字段或来源字段不属于模型输出协议；合法空更新可正常完成。
- 非 combat 模块各返回零个或一个更新可通过数量校验；跨树或批量正文不增加名额。combat 允许多个不同的已发送候选，不占 skill 名额；超限不静默截断。
- 模块选择、楼层范围及自动／手动模式按保存配置发送；本侧准确传递请求戳与处理范围，重复应用和成就进度验收归本地侧。
- 请求准备、发送、返回及提交期间的聊天切换、输入／配置／内容身份变化不会错误落库；普通存档编辑允许最新状态合并，缺失前置及失效任务仍拒绝。超时、取消、协议失败及保存失败不报成功。
- 配置保存、重新载入、模型列表、连接测试、密钥清除和断网提示可用；未保存草稿不能发送。
- 在目标酒馆环境真实验证文本连接、世界书读取、MVU 时序和一次完整保存回读；生图若纳入首版，须实际产出并读取图片。类型检查、单元测试和打包成功不能替代这些联调。
